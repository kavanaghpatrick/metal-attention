## Learnings
- Existing Rwkv7Block (642 lines, 7 tests) + simplified WKV kernel (100 lines) provide strong foundation
- GGUF architecture detection works for RWKV (time_mix + channel_mix patterns)
- Existing GpuForwardPass is transformer-specific (KV cache, attention, RoPE) → separate GpuRwkv7ForwardPass needed
- RWKV-7 7.2B has ~30 tensor types per layer (LoRA projections, GroupNorm, fused lerp) → architectures.rs needs 30+ new mappings
- Recurrent state: 32 MB fixed (64 heads x 64 x 64 x 32 layers) vs transformer KV cache growth
- Q4_0 matvec kernel (existing) reusable for 6 full-rank projections per layer
- RMSNorm kernel (existing) adaptable to LayerNorm (add bias support) and GroupNorm (add grouping)
- GPU Forge KB finding [922]: llama.cpp WKV kernel for RWKV consumes only ~2% CPU time (1.6B model), low priority for GPU acceleration → but we're doing 7.2B on M4 Pro, GPU may help
- Full WKV-7 recurrence (delta rule, data-dependent decay) is complex: state = diag(w)*state + state@ab + v^T*k
- GroupNorm (64 groups, 64 elements/group) needs per-group reduction → threadgroup memory + simdgroup reduction
- LoRA projections (ranks 32-128) are small matvecs → may benefit from specialized kernel vs generic Q4_0 matvec
